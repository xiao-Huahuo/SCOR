| 01 | [Deep Reinforcement Learning from Human Preferences](https://proceedings.neurips.cc/paper/7017-deep-reinforcement-learning-from-human-preferences.pdf)<br>NeurIPS 2017 | 复杂任务缺少可直接编写的 reward，人类又无法持续给每个状态和动作打分。 | 让人只比较两段 trajectory 哪个更好，用偏好数据训练 reward predictor，再用预测 reward 训练 policy。 | 循环执行 policy rollout、抽取 trajectory segment、请求成对偏好、更新 reward model、再更新 policy。Reward predictor 可使用 ensemble，模型分歧可以表示监督不确定性并指导下一批查询。 | 偏好采用 Bradley-Terry 形式：$P(\sigma^1\succ\sigma^2)=\frac{e^{\sum_{t\in\sigma^1}\hat r_\psi}}{e^{\sum_{t\in\sigma^1}\hat r_\psi}+e^{\sum_{t\in\sigma^2}\hat r_\psi}}$，再以偏好交叉熵训练 $\hat r_\psi$。 | 支撑 HED 与 RR。Verifier ensemble 的 disagreement 可作为历史 reward 的可疑度；缺少 ground truth 时，独立 reward model 可以给 RR 提供第二套监督。 | HED 无需从零学习“错误检测器”，可以先用 delayed evidence 与 verifier disagreement 做 audit；RR 可用独立 ensemble 表达 reward uncertainty。 |
| 02 | [PEBBLE: Feedback-Efficient Interactive Reinforcement Learning via Relabeling Experience and Unsupervised Pre-training](https://proceedings.mlr.press/v139/lee21i/lee21i.pdf)<br>ICML 2021 | Preference-based RL 的人工反馈昂贵，reward model 持续变化后，replay buffer 中旧 reward 会失效。 | 先无监督预训练得到多样行为，再主动选择高信息量片段请求偏好；reward model 更新后，重新给历史 experience 打 reward，并继续 off-policy RL。 | 使用无监督 intrinsic objective 预训练 policy；从 replay buffer 中主动选择 pairwise query；训练 preference reward model；每次 reward model 更新后 relabel replay buffer，再由 SAC 等 off-policy learner 使用新的 reward 训练。 | 偏好概率沿用 Bradley-Terry reward-sum 模型；历史重标记可写为 $r_i\leftarrow\hat r_\psi(s_i,a_i)$，更新后的 reward model 会重新作用于 replay buffer 中的旧经验。 | RR 最直接的前置工作，同时给 HED 提供 active query 思路。Correct 路径中的“保留 trajectory，只更新 reward”与 PEBBLE 的 historical relabeling 高度一致。 | RR 第一版可以直接采用 PEBBLE-style relabeling，把创新集中到 CSS 与 TRA。 |
| 03 | [ECHO: No More Stale Feedback: Co-Evolving Critics for Open-World Agent Learning](https://aclanthology.org/2026.acl-long.576.pdf)<br>ACL 2026 | Policy 持续变化后，固定 critic 面对新的 trajectory distribution 和 error pattern 会逐渐 stale，反馈质量下降。 | 让 policy 与 critic 使用同一批 on-policy 数据同步演化，并通过 critic 诊断和 trajectory refinement 构造学习信号。 | Policy 先产生原始 trajectory，critic 诊断错误并指导 refinement；比较原始与修正结果形成 critic 和 policy 的 group-relative training signal，两者使用同步的 on-policy batch 更新。 | 论文使用 saturation-aware gain：$g(s_o,s_r)=\ln\frac{1-s_o+\eta}{1-s_r+\eta}$，用修正前后得分变化衡量 critic 建议带来的增益。 | 支撑 HED 和 RR。新旧 critic 对相同历史 trajectory 的稳定分歧可作为 audit 信号；RR 可以使用当前更可靠的 critic 重新评价历史 trajectory。 | Verifier drift 可以成为 HED 的触发证据，原始出错 Verifier 无需承担唯一的重评价来源。 |
| 04 | [EvoRS: On-Policy Self-Evolution of Reward Systems for Open-Ended Reinforcement Learning](https://arxiv.org/pdf/2609.12459.pdf)<br>arXiv 2026 | 固定 reward system 随 policy 演化会出现判别能力下降、reward hacking 和规则失配。 | 把 reward system 表示成可执行 Reward-DAG，由 agentic designer 根据最新 on-policy rollout 和节点级 trace 诊断并修改 reward system。 | Reward-DAG 的节点各自检查某类属性；系统记录节点输出与整体奖励，designer 基于失败案例提出有限的图结构或参数编辑，对候选 reward system 使用匹配案例比较，再选出更新版本。 | Reward system 表示为 $D_t=(V_t,E_t,\Theta_t)$；整体 reward 可写成 $r_D(x,y)=F_{out}(\{h_v:v\in Pa(out)\};\theta_{out})$。 | 支撑 HED/RR 的 reward-system drift 视角。不同版本 Reward-DAG 对历史样本的评价变化可形成 delayed evidence。 | SCOR 可以把 Verifier 版本变化记录进训练历史，让 HED 与 RR 利用“新 reward system 对旧样本的修订”而不是只依赖单次重新评分。 |
