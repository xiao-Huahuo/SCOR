# SCOR 四个子算法可借鉴文献

文献按 SCOR 的四个子算法分为 HED、CSS、TRA、RR 四个顶层目录。跨子算法文献会在相关目录中重复出现，便于每个子算法独立阅读；README 中的分析保留原来的痛点、机制、公式、与 SCOR 的联系和启示。

运行 `python download_papers.py` 后，论文 PDF 会直接下载到对应子算法目录下的 `编号_简称/编号_简称.pdf`。Windows 可运行 `download_papers.bat`，macOS/Linux 可运行 `download_papers.command`。

目录：

```text
SCOR_related_papers_by_algorithm/
├── 01_HED_Historical_Error_Discovery/
├── 02_CSS_Contamination_Set_Search/
├── 03_TRA_Trajectory_Reusability_Assessment/
└── 04_RR_Reward_Reassessment/
```

## 01_HED_Historical_Error_Discovery

| 编号 | 论文名 | 痛点 | 解决方案 | 详细解决方法 | 核心公式与解释 | 与当前方向的联系 | 启示 |
| -- | --- | -- | ---- | ------ | ------- | -------- | ------ |
| 01 | [Deep Reinforcement Learning from Human Preferences](https://proceedings.neurips.cc/paper/7017-deep-reinforcement-learning-from-human-preferences.pdf)<br>NeurIPS 2017 | 复杂任务缺少可直接编写的 reward，人类又无法持续给每个状态和动作打分。 | 让人只比较两段 trajectory 哪个更好，用偏好数据训练 reward predictor，再用预测 reward 训练 policy。 | 循环执行 policy rollout、抽取 trajectory segment、请求成对偏好、更新 reward model、再更新 policy。Reward predictor 可使用 ensemble，模型分歧可以表示监督不确定性并指导下一批查询。 | 偏好采用 Bradley-Terry 形式：$P(\sigma^1\succ\sigma^2)=\frac{e^{\sum_{t\in\sigma^1}\hat r_\psi}}{e^{\sum_{t\in\sigma^1}\hat r_\psi}+e^{\sum_{t\in\sigma^2}\hat r_\psi}}$，再以偏好交叉熵训练 $\hat r_\psi$。 | 支撑 HED 与 RR。Verifier ensemble 的 disagreement 可作为历史 reward 的可疑度；缺少 ground truth 时，独立 reward model 可以给 RR 提供第二套监督。 | HED 无需从零学习“错误检测器”，可以先用 delayed evidence 与 verifier disagreement 做 audit；RR 可用独立 ensemble 表达 reward uncertainty。 |
| 02 | [PEBBLE: Feedback-Efficient Interactive Reinforcement Learning via Relabeling Experience and Unsupervised Pre-training](https://proceedings.mlr.press/v139/lee21i/lee21i.pdf)<br>ICML 2021 | Preference-based RL 的人工反馈昂贵，reward model 持续变化后，replay buffer 中旧 reward 会失效。 | 先无监督预训练得到多样行为，再主动选择高信息量片段请求偏好；reward model 更新后，重新给历史 experience 打 reward，并继续 off-policy RL。 | 使用无监督 intrinsic objective 预训练 policy；从 replay buffer 中主动选择 pairwise query；训练 preference reward model；每次 reward model 更新后 relabel replay buffer，再由 SAC 等 off-policy learner 使用新的 reward 训练。 | 偏好概率沿用 Bradley-Terry reward-sum 模型；历史重标记可写为 $r_i\leftarrow\hat r_\psi(s_i,a_i)$，更新后的 reward model 会重新作用于 replay buffer 中的旧经验。 | RR 最直接的前置工作，同时给 HED 提供 active query 思路。Correct 路径中的“保留 trajectory，只更新 reward”与 PEBBLE 的 historical relabeling 高度一致。 | RR 第一版可以直接采用 PEBBLE-style relabeling，把创新集中到 CSS 与 TRA。 |
| 03 | [ECHO: No More Stale Feedback: Co-Evolving Critics for Open-World Agent Learning](https://aclanthology.org/2026.acl-long.576.pdf)<br>ACL 2026 | Policy 持续变化后，固定 critic 面对新的 trajectory distribution 和 error pattern 会逐渐 stale，反馈质量下降。 | 让 policy 与 critic 使用同一批 on-policy 数据同步演化，并通过 critic 诊断和 trajectory refinement 构造学习信号。 | Policy 先产生原始 trajectory，critic 诊断错误并指导 refinement；比较原始与修正结果形成 critic 和 policy 的 group-relative training signal，两者使用同步的 on-policy batch 更新。 | 论文使用 saturation-aware gain：$g(s_o,s_r)=\ln\frac{1-s_o+\eta}{1-s_r+\eta}$，用修正前后得分变化衡量 critic 建议带来的增益。 | 支撑 HED 和 RR。新旧 critic 对相同历史 trajectory 的稳定分歧可作为 audit 信号；RR 可以使用当前更可靠的 critic 重新评价历史 trajectory。 | Verifier drift 可以成为 HED 的触发证据，原始出错 Verifier 无需承担唯一的重评价来源。 |
| 04 | [EvoRS: On-Policy Self-Evolution of Reward Systems for Open-Ended Reinforcement Learning](https://arxiv.org/pdf/2609.12459.pdf)<br>arXiv 2026 | 固定 reward system 随 policy 演化会出现判别能力下降、reward hacking 和规则失配。 | 把 reward system 表示成可执行 Reward-DAG，由 agentic designer 根据最新 on-policy rollout 和节点级 trace 诊断并修改 reward system。 | Reward-DAG 的节点各自检查某类属性；系统记录节点输出与整体奖励，designer 基于失败案例提出有限的图结构或参数编辑，对候选 reward system 使用匹配案例比较，再选出更新版本。 | Reward system 表示为 $D_t=(V_t,E_t,\Theta_t)$；整体 reward 可写成 $r_D(x,y)=F_{out}(\{h_v:v\in Pa(out)\};\theta_{out})$。 | 支撑 HED/RR 的 reward-system drift 视角。不同版本 Reward-DAG 对历史样本的评价变化可形成 delayed evidence。 | SCOR 可以把 Verifier 版本变化记录进训练历史，让 HED 与 RR 利用“新 reward system 对旧样本的修订”而不是只依赖单次重新评分。 |


## 02_CSS_Contamination_Set_Search

| 编号 | 论文名 | 痛点 | 解决方案 | 详细解决方法 | 核心公式与解释 | 与当前方向的联系 | 启示 |
| -- | --- | -- | ---- | ------ | ------- | -------- | ------ |
| 01 | [A Snapshot of Influence: A Local Data Attribution Framework for Online Reinforcement Learning](https://papers.nips.cc/paper_files/paper/2025/file/377d0752059d3d4686aa021b664a25dd-Paper-Conference.pdf)<br>NeurIPS 2025 | Online RL 中训练 experience 会改变当前 policy，并进一步改变未来采集的数据，固定数据集假设下的数据归因方法难以直接使用。 | 在训练 checkpoint 上进行 local data attribution，用训练记录梯度与目标行为或累计回报目标的梯度相似度估计 influence，并用 Iterative Influence-based Filtering 过滤有害经验。 | 针对指定 checkpoint 和 target function 计算每条训练记录的局部影响；分别考虑 action 与 cumulative return 目标；高影响记录可被过滤，再观察 policy 的行为变化。 | 局部梯度相似度可概括为 $I(z_i;T)=\langle\nabla_\theta\ell(z_i;\theta),\nabla_\theta T(\theta)\rangle$。它衡量训练记录 $z_i$ 的更新方向与目标 $T$ 的变化方向是否一致。 | CSS 最直接的算法底座。SCOR 需要在此基础上加入 delayed historical reward revision，并追踪 $\delta\theta_k\rightarrow\delta D_{k+1}\rightarrow\cdots$ 的 descendant contamination。 | CSS 无需从零发明 influence estimator；主要创新可以放在跨 outer-loop 传播、随机分叉校准、污染集恢复与主动 probe。 |
| 02 | [Understanding Black-box Predictions via Influence Functions](https://proceedings.mlr.press/v70/koh17a/koh17a.pdf)<br>ICML 2017 | 逐个删除训练样本再完整重训才能知道其影响，计算成本过高。 | 利用 influence function 近似“对某个训练样本施加微小 upweight”后参数和测试损失如何变化。 | 先求训练目标 Hessian 与单个样本梯度，再用 inverse-Hessian-vector product 估计该样本对参数和指定测试点的影响，无需逐样本重新训练。 | $I_{up,loss}(z,z_{test})=-\nabla_\theta L(z_{test},\hat\theta)^T H_{\hat\theta}^{-1}\nabla_\theta L(z,\hat\theta)$。负值与正值分别表示 upweight 后对目标损失的不同影响方向。 | CSS 的经典 baseline，可在小模型或受控环境中估计第 $k$ 轮训练事件对后续状态的局部影响。 | 大型 VLM 上 inverse Hessian 成本高，适合作为理论参照或小规模 benchmark，而非 SCOR 主实现。 |
| 03 | [Estimating Training Data Influence by Tracing Gradient Descent](https://proceedings.neurips.cc/paper/2020/file/e6385d39ec9394f2f3a354d9d2b88eec-Paper.pdf)<br>NeurIPS 2020 | Influence Functions 需要 Hessian 近似，在深度网络中计算昂贵且局部二阶假设容易失效。 | 沿真实训练轨迹保存多个 checkpoint，用训练样本与目标样本梯度的点积累计影响。 | 训练时周期保存参数 checkpoint；在每个 checkpoint 上计算 source 和 target 的梯度相似度；使用学习率加权后跨 checkpoint 求和，得到训练过程中的累计 influence。 | $TracInCP(x,x_j)=\sum_i\eta_i\,g_{\theta_i}(x)^Tg_{\theta_i}(x_j)$，其中 $\theta_i$ 为 checkpoint，$\eta_i$ 为对应学习率。 | SCOR 本来就需要 outer-loop checkpoint，TracIn 很适合成为 CSS 的低成本历史 influence baseline。 | CSS 可以先用 TracIn/gradient alignment 粗筛候选污染轮次，再对边界样本执行更昂贵的 counterfactual probe。 |
| 04 | [Causal Agent Replay: Counterfactual Attribution for LLM-Agent Failures](https://arxiv.org/pdf/2606.08275.pdf)<br>arXiv 2026 | LLM Agent 的失败轨迹具有随机性，仅靠日志相似度或 LLM judge 很难确定哪个决策真正导致最终失败。 | 把 Agent execution 建模为结构因果过程，对特定步骤实施 intervention，再从该点向后多次 replay，利用结果分布变化估计因果贡献。 | 选择候选步骤，替换该处 action 或决策；保持其余可控条件一致，多次重新运行 stochastic policy；比较 factual 与 intervention outcome distribution，并用置信区间和 Monte-Carlo Shapley 处理多步交互。 | 单步因果效应可概括为 $\Delta_t=\mathbb E[Y\mid do(A_t=a_t')] - \mathbb E[Y]$；多次 replay 用于估计该期望及其置信区间。 | CSS 的 Active Contamination Probe 和 TRA 的随机性校准都可借鉴 CAR。 | 单次 replay 的差异不适合作为污染或 trajectory 失效证据；重复 replay 与置信区间可以成为 SCOR 稳定判定的统计基础。 |
| 05 | [Machine Unlearning](https://arxiv.org/pdf/1912.03817.pdf)<br>IEEE S&P 2021 | 删除训练数据后从头 retrain 才能得到干净模型，成本与原训练基本相同。 | 提出 SISA：Sharded、Isolated、Sliced、Aggregated。预先切分训练数据并保存 slice checkpoint，删除数据时只重训受影响 shard 的必要后缀。 | 数据先分成互相隔离的 shards，每个 shard 再按时间切成 slices；每个 slice 后保存 checkpoint；删除请求定位到对应 shard/slice，从前一 checkpoint 重训该 shard，最后重新 aggregate constituent models。 | 可抽象为 $D=\bigsqcup_{s=1}^SD_s$，$D_s=D_{s,1}\oplus\cdots\oplus D_{s,R}$，最终 $f(x)=Agg(f_1(x),\ldots,f_S(x))$。 | SCOR 整体 selective rollback 的直接祖先。SISA 的受影响范围由预先分片确定，SCOR 的 $C_k$ 需要从 self-generated training path 中动态搜索。 | SCOR 可以继承 checkpoint/slice 的工程思想，把新贡献集中在“动态污染范围如何发现”。 |
| 06 | [DeltaGrad: Rapid retraining of machine learning models](https://proceedings.mlr.press/v119/wu20b/wu20b.pdf)<br>ICML 2020 | 训练数据发生少量增删后，全量重训浪费大量与原训练重复的梯度计算。 | 缓存原训练过程中的参数和梯度，利用 Taylor 展开与 L-BFGS 近似数据变更后的新梯度，只周期性执行精确更新。 | 原训练阶段保存 $w_t$ 与 gradient；数据变更后，用参数差与 Hessian 近似估计新模型的梯度变化；以 L-BFGS 构造低成本 quasi-Hessian，并定期执行 exact gradient refresh 控制累计误差。 | $\nabla F(w_t^I)\approx\nabla F(w_t)+H_t(w_t^I-w_t)$，实际使用 L-BFGS 近似 $H_t$。 | 可用于降低 SCOR Reuse/Correct 的重训练成本，尤其适合历史 computation 已保存的情况。 | SCOR 的论文贡献无需放在“怎样更快重算梯度”上，可以复用 DeltaGrad 类方法作为工程加速或 baseline。 |


## 03_TRA_Trajectory_Reusability_Assessment

| 编号 | 论文名 | 痛点 | 解决方案 | 详细解决方法 | 核心公式与解释 | 与当前方向的联系 | 启示 |
| -- | --- | -- | ---- | ------ | ------- | -------- | ------ |
| 01 | [Remember and Forget for Experience Replay](https://proceedings.mlr.press/v97/novati19a/novati19a.pdf)<br>ICML 2019 | Replay buffer 中历史 experience 由旧 policy 产生，随着 policy 更新会越来越 off-policy，直接训练会增加偏差和方差。 | 根据 importance ratio 把历史 experience 分为 near-policy 与 far-policy；忽略过远经验的梯度，并用 KL 约束控制当前 policy 偏离 replay policy 的速度。 | 计算当前 policy 与生成该动作的 behavior policy 的概率比；超出允许区间的 experience 不参与 actor 更新；额外正则让 policy 保持在 replay 分布附近。 | $\rho_t=\frac{\pi_w(a_t\mid s_t)}{\mu_t(a_t\mid s_t)}$。$\rho_t$ 远离 $1$ 时，历史 action 在当前 policy 下的支持减弱。 | TRA 的第一层低成本 support test。可先过滤明显 far-policy 的历史 trajectory，再进入 Agent-specific branch replay。 | TRA 无需从零设计“旧数据离当前模型有多远”的指标；创新应集中在多步 tool-agent 的行为分支可复用性。 |
| 02 | [IMPALA: Scalable Distributed Deep-RL with Importance Weighted Actor-Learner Architectures](https://proceedings.mlr.press/v80/espeholt18a/espeholt18a.pdf)<br>ICML 2018 | 分布式 RL 中 actor 与 learner 解耦后，actor 产生 trajectory 时使用的 policy 会落后于 learner，形成 policy lag。 | 提出 V-trace，用截断 importance weight 修正 stale actor trajectory 对 value 和 policy update 的影响。 | Actor 并行生成 trajectory，learner 持续更新参数；V-trace 使用 $\pi/\mu$ 的截断权重修正多步 TD target，使一定程度的 stale trajectory 仍可训练。 | $v_s=V(x_s)+\sum_{t=s}^{s+n-1}\gamma^{t-s}(\prod_{i=s}^{t-1}c_i)\delta_tV$，其中 $\delta_tV=\rho_t[r_t+\gamma V(x_{t+1})-V(x_t)]$，$\rho_t,c_t$ 为截断 importance ratio。 | TRA 可据此区分“需要 Regenerate”的严重分布偏移与“可通过 off-policy correction 继续使用”的中等偏移。 | Correct 可以包含适度的 importance correction，trajectory 有偏移不等于必须重新 rollout。 |
| 03 | [Prosperity before Collapse: How Far Can Off-Policy RL Reach with Stale Data on LLMs?](https://proceedings.iclr.cc/paper_files/paper/2026/file/8590b946e4f0c2b1262cb5b047924653-Paper-Conference.pdf)<br>ICLR 2026 | LLM RL 为提高吞吐量会重复使用 stale rollout，但普通 importance ratio 在 policy drift 增大后容易出现高方差和训练崩溃。 | 用 importance-weight log-ratio 的二阶矩刻画 staleness 风险，并以 second-moment trust region 限制高风险 token/experience。 | 估计 behavior policy 与当前 policy 的 log importance ratio 二阶矩；利用其与 $\chi^2$ divergence 的关系控制分布偏移；当平均风险超阈值时优先屏蔽高风险 token。 | $\hat M_2=\frac1N\sum_i[\log\frac{\pi_\theta(a_i\mid s_i)}{\pi_{behav}(a_i\mid s_i)}]^2$；在 bounded ratio 条件下有 $\chi^2(\pi_{new}\\ | \pi_{behav})\le R^2M_2$。 | TRA 很接近的 LLM-RL 前置。可以用 $M_2$ 作为 trajectory support/staleness 指标，而不是按“经历了多少次 update”直接淘汰。 |
| 04 | [ExGRPO: Learning to Reason from Experience](https://proceedings.iclr.cc/paper_files/paper/2026/file/15a296dc96baa12aaef4facdd391161f-Paper-Conference.pdf)<br>ICLR 2026 | 标准 GRPO 每轮主要依赖新 rollout，历史中已经得到的高价值 reasoning experience 没有被充分复用；盲目 replay 又会引入 off-policy 偏差。 | 维护 experience pool，用 rollout correctness 与 entropy 评估历史 reasoning experience，再将高价值旧经验与新 rollout 混合用于 GRPO。 | 优先选择具有正确结果且 uncertainty 较低的历史 reasoning；从 experience pool 中选择低 entropy trajectory；每个训练 group 同时包含 past experience 与 fresh rollout，并配合 mixed-policy/off-policy correction。 | 经验选择可写为 $o^*=\arg\min_{o_i}H(o_i;\pi_\theta)$，在满足 correctness 条件的候选 experience 中优先选择低 entropy trajectory。 | TRA 可借 correctness、entropy、mixed fresh/history group 等经验价值信号；也支撑后续 partial-reuse group。 | TRA 可以把“可复用”与“值得复用”分开：前者看 policy support，后者可吸收 ExGRPO 的 correctness/entropy 信号。 |
| 05 | [Causal Agent Replay: Counterfactual Attribution for LLM-Agent Failures](https://arxiv.org/pdf/2606.08275.pdf)<br>arXiv 2026 | LLM Agent 的失败轨迹具有随机性，仅靠日志相似度或 LLM judge 很难确定哪个决策真正导致最终失败。 | 把 Agent execution 建模为结构因果过程，对特定步骤实施 intervention，再从该点向后多次 replay，利用结果分布变化估计因果贡献。 | 选择候选步骤，替换该处 action 或决策；保持其余可控条件一致，多次重新运行 stochastic policy；比较 factual 与 intervention outcome distribution，并用置信区间和 Monte-Carlo Shapley 处理多步交互。 | 单步因果效应可概括为 $\Delta_t=\mathbb E[Y\mid do(A_t=a_t')] - \mathbb E[Y]$；多次 replay 用于估计该期望及其置信区间。 | CSS 的 Active Contamination Probe 和 TRA 的随机性校准都可借鉴 CAR。 | 单次 replay 的差异不适合作为污染或 trajectory 失效证据；重复 replay 与置信区间可以成为 SCOR 稳定判定的统计基础。 |
| 06 | [TrajDeleter: Enabling Trajectory Forgetting in Offline Reinforcement Learning Agents](https://www.ndss-symposium.org/wp-content/uploads/2025-126-paper.pdf)<br>NDSS 2025 | Offline RL 需要删除指定 trajectory 的训练影响，同时保留其余 trajectory 上的 policy utility。 | 先执行 forgetting phase 压低待删除 trajectory 的影响并保持 retained trajectories，再执行 convergence phase 恢复保留数据上的 value；同时用 TrajAuditor 检查遗忘是否完成。 | 将数据分为 forget set $D_f$ 与 maintain set $D_m$；第一阶段对两类数据施加相反优化方向；第二阶段约束删除后 policy 的 Q/value 在 $D_m$ 上接近原模型；TrajAuditor 用 value-vector 分布判断目标 trajectory 是否仍可被识别。 | 第一阶段可写为 $\nabla L_1=\mathbb E_{D_m}[\nabla\log\pi' A^{\pi'}]-\lambda\mathbb E_{D_f}[\nabla\log\pi' A^{\pi'}]$；收敛阶段 $L_2=\mathbb E_{(s,a)\sim D_m}[Q_\theta^{\pi'}(s,a)-Q^\pi(s,a)]^2$。 | SCOR 的 trajectory-level RL unlearning 强 baseline，也可借 TrajAuditor 设计历史污染是否清除的评价。 | TrajDeleter 面向固定 offline dataset；SCOR 的新增难点是错误参数还会改变后续 self-generated data，因此需要 CSS 搜索 descendant training units。 |
