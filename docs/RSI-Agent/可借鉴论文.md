### 可借鉴文献及其机制

四个子算法不需要全部从零设计。现有工作已经分别覆盖了历史监督审计、训练数据归因、off-policy trajectory reuse、reward relabeling 等问题。SCOR 可以直接复用其中成熟部分，把主要创新集中在 **CSS 的跨外循环污染搜索** 和 **TRA 的 Agent 轨迹可复用性判定**。

#### 1. Historical Error Discovery（HED）

HED 需要解决的是：训练已经推进到后续轮次以后，如何发现某个历史 reward 当时判错了，并决定哪些历史记录值得优先重新检查。

**Deep Reinforcement Learning from Human Preferences，NeurIPS 2017**

该工作训练多个 reward predictor，并利用 ensemble disagreement 估计当前 reward model 的不确定性。系统从候选 trajectory segment 中优先选择预测分歧较大的样本请求人工反馈。[NeurIPS 会议论文集](https://proceedings.neurips.cc/paper/7017-deep-reinforcement-learning-from-human-preferences.pdf?utm_source=chatgpt.com)

可借鉴到 HED：

- 用多个 Verifier 的 disagreement 作为历史 reward 可疑度；
- 将高 disagreement 的历史 trajectory 优先加入 audit；
- HED 的 $P(error_k\mid E)$ 可以部分由 verifier ensemble uncertainty 构成。

**PEBBLE，ICML 2021**

PEBBLE 使用主动查询选择最有信息量的行为片段获取 preference feedback。Reward model 更新以后，它会重新给 replay buffer 中的历史经验打 reward。[Proceedings of Machine Learning Research](https://proceedings.mlr.press/v139/lee21i.html?utm_source=chatgpt.com)

HED 可以借它的 active query 思路：历史记录规模很大时，只检查 error probability、uncertainty 或 downstream influence 较高的部分。PEBBLE 同时也是 RR 最直接的前置工作。

**ECHO，ACL 2026**

ECHO 研究 policy 不断变化以后 static critic 逐渐 stale 的问题，通过 policy 和 critic 的同步训练，让 critic 跟随当前 trajectory distribution 和 error pattern 演化。[ACL Anthology](https://aclanthology.org/2026.acl-long.576/?utm_source=chatgpt.com)

它可以给 HED 提供一个触发信号：当新旧 Verifier 对相同历史状态的评价发生明显变化，或者当前 critic 与历史 critic 出现稳定分歧时，启动历史审计。ECHO 本身处理当前 critic 的更新，并不负责修复已经进入参数的历史错误。

**EvoRS，2026 preprint**

EvoRS 进一步把整个 reward system 视为随 policy 演化的对象，指出固定 reward system 在 policy 变化后会出现 reward hacking、判别能力下降等问题，并从新的 on-policy experience 中更新 Reward-DAG。[arXiv](https://arxiv.org/abs/2609.12459?utm_source=chatgpt.com)

HED 可以借鉴 reward-system drift 的思想，把 Verifier 或 reward system 的版本变化作为历史 reward revision 的证据来源。

因此，第一版 HED 可以先采用：

\[ \text{Delayed Evidence} + \text{Verifier Disagreement} + \text{Reward-system Drift} + \text{Downstream Influence} \]

进行历史 audit 排序，而无需单独设计一套复杂的新检测模型。

#### 2. Contamination Set Search（CSS）

CSS 负责寻找：

\[ C_k=\{G_t:\text{第 }k\text{ 轮错误对 }G_t\text{ 产生有效影响}\} \]

这一部分已有很强的数据归因基础，但现有方法主要做局部 attribution，SCOR 还要处理错误参数改变未来 self-generated data 后形成的跨轮传播。

**A Snapshot of Influence: A Local Data Attribution Framework for Online Reinforcement Learning，NeurIPS 2025**

这是 CSS 最直接的前置工作。论文指出 online RL 中一条 experience 同时影响当前 policy update 和未来数据收集，因此固定数据集的数据归因假设不再成立。其方法针对 action 和 cumulative return 定义 target function，再使用 training loss gradient 与 target gradient 的 similarity 衡量一条训练记录的 influence，并进一步提出 Iterative Influence-based Filtering。[NeurIPS 会议论文集](https://proceedings.neurips.cc/paper_files/paper/2025/hash/377d0752059d3d4686aa021b664a25dd-Abstract-Conference.html?utm_source=chatgpt.com)

CSS 可以直接借：

- gradient similarity 作为历史 training unit 的基础 influence estimator；
- checkpoint-local attribution；
- action influence 与 return influence 两种目标；
- IIF 式迭代过滤。

SCOR 需要继续扩展的部分是：

\[ \text{Historical Reward Error} \rightarrow \delta\theta_k \rightarrow \delta D_{k+1} \rightarrow \delta\theta_{k+1} \rightarrow\cdots \]

即从 local influence 扩展到 **delayed historical error 的 descendant contamination set**。

**Influence Functions，ICML 2017**

Influence Functions 通过梯度和 Hessian-vector product 估计一个训练样本对模型预测的影响，可以追溯哪些训练数据最影响某个结果。[Proceedings of Machine Learning Research](https://proceedings.mlr.press/v70/koh17a?utm_source=chatgpt.com)

CSS 可以把它作为经典 baseline，也可以借它定义“移除或修改第 $k$ 轮 training event 后，目标状态变化多少”的局部近似。大型 VLM 上二阶计算成本较高，因此更适合作为理论参照或小规模实验 baseline。

**TracIn，NeurIPS 2020**

TracIn 使用训练过程中保存的 checkpoints，通过一阶 gradient similarity 追踪某个训练样本对目标预测的累计影响，避免 Influence Functions 中昂贵的 Hessian 计算。[NeurIPS 会议论文集](https://proceedings.neurips.cc/paper/2020/hash/e6385d39ec9394f2f3a354d9d2b88eec-Abstract.html?utm_source=chatgpt.com)

SCOR 本来就需要保存 outer-loop checkpoint，因此 TracIn 和 CSS 很契合。可以沿历史 checkpoints 计算第 $k$ 轮错误与后续 $G_t$ 的 gradient alignment，作为污染候选分数。

**Causal Agent Replay（CAR），2026 preprint**

CAR 将 Agent trajectory 建模为结构因果模型，在某个 step 上执行 intervention，再让 stochastic policy 多次重新向后运行，通过 outcome distribution 的变化估计因果影响，并为估计结果给出置信区间。它还使用 Monte-Carlo Shapley 处理多个步骤共同造成结果的情况。[arXiv](https://arxiv.org/abs/2606.08275?utm_source=chatgpt.com)

CSS 的 Active Contamination Probe 可以直接借这一思路：

1. 固定第 $t$ 轮之前的状态；
2. 替换或修正第 $k$ 轮产生的影响；
3. 多次重新向后 rollout；
4. 比较结果分布；
5. 用 confidence interval 区分真实污染与随机分叉。

这样 CSS 可以形成两级搜索：先用 Snapshot of Influence、TracIn 等低成本归因筛选候选 $C_k$，边界样本再用 CAR 式 intervention 做主动确认。

#### 3. Trajectory Reusability Assessment（TRA）

TRA 处理的问题是：$G_t$ 已经确认受到污染以后，历史 $Trajectory_t$ 是否仍能作为当前 Repair Model 的训练数据。

这一问题与 off-policy experience reuse 高度相关。

**ReF-ER：Remember and Forget for Experience Replay，ICML 2019**

ReF-ER 判断 replay buffer 中的历史 experience 与当前 policy 是否仍足够接近。对当前 policy 下概率过低的历史经验直接跳过其 gradient，同时限制当前 policy 不要过快偏离 replay behavior。[Proceedings of Machine Learning Research](https://proceedings.mlr.press/v97/novati19a.html?utm_source=chatgpt.com)

TRA 可以直接借：

\[ \rho= \frac{\pi_{repair}(a\mid s)} {\pi_{hist}(a\mid s)} \]

作为第一层低成本 support test。极端 far-policy 的 trajectory 可以直接判为高风险，无需继续执行昂贵 Probe。

**IMPALA / V-trace，ICML 2018**

IMPALA 中 actor 生成 trajectory 时使用的 policy 与 learner 更新时的 policy 会产生 lag，因此训练天然带有 off-policy discrepancy。V-trace 使用 importance weighting 修正这种差异。[Proceedings of Machine Learning Research](https://proceedings.mlr.press/v80/espeholt18a?utm_source=chatgpt.com)

TRA 可以从中借到一个重要区分：历史 trajectory 与当前 policy 有一定偏移时，并不一定立即丢弃，可以先进行 off-policy correction；只有偏移超过可控范围时再 Regenerate。

**M2PO：Prosperity before Collapse，ICLR 2026**

M2PO 专门研究 LLM RL 中 stale rollout 的复用问题。它发现 stale data 本身仍可以包含有效训练信息，并通过约束 importance weight 的 second moment 控制高方差样本，在实验中处理了跨大量 model updates 的 stale rollout。[ICLR 会议录](https://proceedings.iclr.cc/paper_files/paper/2026/hash/8590b946e4f0c2b1262cb5b047924653-Abstract-Conference.html?utm_source=chatgpt.com)

TRA 可以借：

- importance weight second moment；
- stale rollout stability；
- 极端 importance-weight outlier 检测。

这也支持 TRA 的基本判断：模型参数已经变化，并不自动意味着历史 trajectory 已失效。

**ExGRPO，ICLR 2026**

ExGRPO 研究 RLVR 中哪些历史 reasoning experiences 值得重复使用，发现 rollout correctness 和 entropy 可以作为 experience value 信号，并使用 mixed-policy objective 同时利用新旧经验。[ICLR 会议录](https://proceedings.iclr.cc/paper_files/paper/2026/hash/15a296dc96baa12aaef4facdd391161f-Abstract-Conference.html?utm_source=chatgpt.com)

TRA 可以加入 correctness、entropy 等低成本 trajectory-level 指标，用于筛掉明显无价值或高度异常的历史 trajectory。

**Causal Agent Replay，2026 preprint**

CAR 对 TRA 的主要价值在随机性处理。相同 Agent 和相同状态多次运行也会产生不同 action，因此 CAR 不比较单条 replay trajectory，而是多次运行得到 outcome distribution，并给出 confidence interval。[arXiv](https://arxiv.org/abs/2606.08275?utm_source=chatgpt.com)

TRA 可以直接继承这种 repeated replay 思路，再加入 SCOR 自己的 Agent-specific 部分：

- Decision Anchors；
- Behavior Effect Class；
- Self-Calibrated Branch Support；
- Sequential Reusability Assessment；
- Active Trajectory Probe。

因此 TRA 可以设计成：

\[ \text{ReF-ER/M2PO support test} \rightarrow \text{Agent-specific branch replay} \rightarrow \text{Reusable / Non-Reusable} \]

前半部分采用已有 off-policy 方法，后半部分才承担 SCOR 的主要创新。

#### 4. Reward Reassessment（RR）

RR 的任务最明确：给已经确定采用的 trajectory 重新确定 $Reward^{repair}$。这一部分已有成熟方法，可以优先复用。

**PEBBLE，ICML 2021**

PEBBLE 在 reward model 更新后，会重新计算 replay buffer 中全部历史 experience 的 reward，再使用更新后的 reward 继续 off-policy RL。[Proceedings of Machine Learning Research](https://proceedings.mlr.press/v139/lee21i.html?utm_source=chatgpt.com)

这与 SCOR 的 Correct 路径几乎直接对应：

\[ (\tau^{hist},r^{hist}) \rightarrow (\tau^{hist},r^{repair}) \]

因此 RR 第一版完全可以采用 PEBBLE-style historical reward relabeling。

**Hindsight Experience Replay（HER），NeurIPS 2017**

HER 保留已经发生的 trajectory，通过重新解释 goal，并据此重新计算 reward，让原本失败的经验能够重新用于训练。[arXiv](https://arxiv.org/abs/1707.01495?utm_source=chatgpt.com)

HER 的任务背景与 SCOR 不同，但它提供了一个重要先例：**trajectory 本身可以保持不变，而其监督信号根据新的解释重新生成。** 这可以作为 Correct 合法性的理论和 related-work 支撑。

**Deep Reinforcement Learning from Human Preferences，NeurIPS 2017**

当 ground truth 或 executable checker 不存在时，可以训练 reward predictor ensemble，并利用 ensemble disagreement 表达 reward uncertainty。[NeurIPS 会议论文集](https://proceedings.neurips.cc/paper/7017-deep-reinforcement-learning-from-human-preferences.pdf?utm_source=chatgpt.com)

RR 可以借此实现：

\[ r^{repair}\pm uncertainty \]

或进一步形成 SCOR 中的 Certified Reward / Advantage interval。

**FunPRM，2026 preprint**

FunPRM 面对 noisy process rewards，利用 unit test 得到的干净 final-solution reward，通过 meta-learning reward correction 修正中间步骤的噪声 reward。[arXiv](https://arxiv.org/abs/2601.22249?utm_source=chatgpt.com)

这一机制与 SCOR 的 delayed reliable evidence 很接近：

\[ \text{later clean evidence} \rightarrow \text{correct earlier noisy reward} \]

VLM 中可以把 unit test 替换成 ground-truth answer、deterministic visual checker、程序执行结果或其他可靠 verifier evidence。

**ECHO / EvoRS**

ECHO 和 EvoRS 都说明 evaluator 或 reward system 会随着 policy distribution 演化而失效，因此 RR 在缺少确定性 ground truth 时，可以使用更新后的 critic、独立 Verifier 或 evolving reward system重新评价历史 trajectory，而不是固定沿用产生原错误 reward 的旧 Verifier。[ACL Anthology](https://aclanthology.org/2026.acl-long.576/?utm_source=chatgpt.com)

RR 第一阶段可以直接采用：

\[ \text{Ground Truth / Executable Checker} > \text{Independent Reliable Verifier} > \text{Verifier Ensemble} \]

并使用 PEBBLE-style relabeling 更新历史 reward。这样 RR 主要承担工程组件角色，无需作为 SCOR 的主要新算法。

#### 5. 对整个 SCOR 修复流程有支撑的工作

**SISA，IEEE S&P 2021** 将训练数据划分为 shard 和 slice，并保存中间 checkpoint。发生删除请求后，只从受到影响的 slice 重新训练，而不是重做整个训练过程。[数字对象标识符](https://doi.org/10.1145/3749987?utm_source=chatgpt.com)

SCOR 的选择性回滚与它有直接联系。SISA 的影响范围由预先设计的数据分片决定，SCOR 的 $C_k$ 则需要根据 self-evolving training 中实际产生的动态影响确定。

**DeltaGrad，ICML 2020** 在训练时缓存历史计算信息，数据发生少量增删后利用这些缓存快速重新训练，降低从头训练的成本。[Proceedings of Machine Learning Research](https://proceedings.mlr.press/v119/wu20b.html?utm_source=chatgpt.com)

SCOR 可以借它的历史 computation reuse 思想，优化 Reuse 和 Correct 阶段的参数重算。

**TrajDeleter，NDSS 2025** 研究 offline RL 中如何消除指定 trajectory 对 agent 的影响，并使用重新训练模型作为参照，同时提出 TrajAuditor 检查 unlearning 是否完成。[NDSS Symposium](https://www.ndss-symposium.org/ndss-paper/trajdeleter-enabling-trajectory-forgetting-in-offline-reinforcement-learning-agents/?utm_source=chatgpt.com)

它适合作为 SCOR 的 trajectory-level unlearning baseline。SCOR 与它的主要区别在于，SCOR 处理 online/self-evolving 环境：历史 trajectory 影响参数以后，参数还会继续改变之后生成的数据，因此修复对象包含 descendant training units。

最终可以把四个子算法的来源关系压缩为：

\[ \text{HED} \leftarrow \text{Active Auditing + Verifier Uncertainty} \]\[ \text{CSS} \leftarrow \text{Online-RL Attribution + Causal Replay} \]\[ \text{TRA} \leftarrow \text{Off-policy Experience Reuse + Agent Replay} \]\[ \text{RR} \leftarrow \text{Historical Reward Relabeling + Reliable Verification} \]

其中 **HED 和 RR 可以较大程度复用已有机制；CSS 需要在 Online-RL Attribution 上解决跨 outer-loop descendant contamination；TRA 需要在 stale experience reuse 上解决 stochastic tool-agent 的行为分支可复用性。** 这样 SCOR 的主要原创工作集中在 CSS 和 TRA，避免四个子算法同时从零开发。
