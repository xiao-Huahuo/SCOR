| 01  | [Agent0-VL: Exploring Self-Evolving Agent for Tool-Integrated Vision-Language Reasoning](https://arxiv.org/pdf/2511.19900)                          | 视觉推理中的 self-reward 主要依赖文本自评，模型很难可靠检查几何关系、数值计算和工具证据，容易给视觉上错误但语言上合理的轨迹高分。                         | 让同一个 LVLM 同时承担 Solver 和 Verifier，并让两种角色都能调用工具。Verifier 对 Solver 的中间步骤做细粒度检查，产生 reward 与 repair signal，再通过 GRPO 更新共享策略。           | ① Solver 对图像与问题执行多轮推理，并按需调用 Python、视觉分析等工具，形成 trajectory。<br>② Verifier 读取推理轨迹，对中间步骤和最终答案进行生成式验证，也能调用工具核实证据。<br>③ Verifier 输出 step-wise score、confidence 与 critique，低置信或失败样本进入 self-repair。<br>④ outcome reward、verify reward、tool reward 和 cost penalty 合成轨迹 reward。<br>⑤ 外层用 GRPO 更新共享 policy，更新后的模型继续同时承担 Solver 和 Verifier，形成多轮 self-evolution。     | 共享策略可写为 $\pi_\theta(a_t\mid s_t,m)$，其中 $m\in\{S,V\}$ 决定当前是 Solver 还是 Verifier。轨迹为 $\tau=\{(s_1,a_1,o_1),\ldots,(s_T,a_T,o_T)\}$。总 reward 可概括为 $g(\tau)=\alpha_1r_{out}+\sum_t(\alpha_2r_{verify,t}+\alpha_3r_{tool,t}-\alpha_4C_t)$。关键点在于 Solver 与 Verifier 共用参数 $\theta$，一次 RL 更新会同时改变两种角色。 | **EvoDrift-VL 的直接起点。** 当前方向研究的正是这一共享参数闭环带来的副作用：$M_t\Rightarrow(S_t,V_t)$ 后，Verifier 也随 generation 更新。必须先确认 Agent0-VL 中角色切换、reward 生成、GRPO 更新和 self-repair 的完整链路。                                                                                              |     |
| 02  | [Preference Leakage: A Contamination Problem in LLM-as-a-judge](https://arxiv.org/pdf/2502.01534.pdf)                                               | LLM-as-a-Judge 与数据生成模型存在关联时，评价结果会受到模型关系影响。一个 Judge 可能系统性偏向由相关 Generator 产生或训练出的模型输出，使自动评估出现污染。  | 明确定义 Generator 与 Judge 的三类关联关系，并通过 related judge 与 unrelated judge 的对照实验测量 preference leakage。                                   | ① 构造三类 relatedness：同一个模型、继承关系、同一模型家族。<br>② 用不同 Generator 合成训练数据，再训练相应 student model。<br>③ 对同一批 student 输出，分别交给与 Generator 相关和无关的 Judge 评价。<br>④ 在 AlpacaEval、Arena-Hard、MT-Bench 等评测中比较相关 Judge 带来的额外偏好，并分析数据比例、模型大小和任务类别等因素。                                                                                                                           | 核心判断可以写为 $\mathbb{E}[S_{M_J}(y_s\mid x)\mid M_G\sim M_J] > \mathbb{E}[S_{M'_J}(y_s\mid x)\mid M_G\not\sim M'_J]$。同一份输出在 Judge 与 Generator 存在关联时获得更高评价，即出现 preference leakage。                                                                                                                | **与 IVD 最接近的前置工作之一。** 它已经覆盖“同源、继承、同家族会导致 Judge 偏好”，因此 EvoDrift-VL 需要进一步证明时间维度上的 **generation-specific + lineage-specific false-accept drift**。$6\times6$ cross-generation cross-lineage matrix 必须把静态 relatedness bias 与训练过程中形成的 co-adaptation interaction 分开。 |     |
| 03  | [CoVerRL: Breaking the Consensus Trap in Label-Free Reasoning via Generator-Verifier Co-Evolution](https://aclanthology.org/2026.acl-long.1376.pdf) | 无标签 RL 常把多数投票答案当作伪标签。训练越强调 self-consistency，输出越集中；当多数答案本身错误时，模型会持续强化同一个系统性错误，形成 consensus trap。 | 让同一个模型在 Generator 与 Verifier 两种角色之间共同进化。Generator 提供候选解和多数投票伪标签，Verifier 学习检查推理并过滤 self-consistent errors，两种能力相互提供训练信号。          | ① Generator 为同一问题采样多个解并通过 majority voting 得到 draft pseudo-label。<br>② Verifier 对多数答案对应的正样本进行检查，剔除“高一致但实际有问题”的轨迹。<br>③ 构造正负 verification samples，让 Verifier 学会区分正确与错误推理。<br>④ 对验证失败样本生成 self-correction trajectory。<br>⑤ 使用 Answer-Anchored GRPO 联合更新 generation、verification、self-correction 三类行为。训练后 Verifier 过滤能力增强，伪标签随之变干净，Generator 获得更可靠的 reward。 | Reward 为 $r=r^f+r^a$，其中 $r^f\in\{0,1\}$ 检查格式，$r^a=\mathbb{I}(o=\hat{o})$ 检查输出是否与目标伪标签一致。Answer-Anchored GRPO 使用 $A_i=\frac{r_i-\operatorname{mean}(r)}{\operatorname{std}(r)}$ 做组内相对优势估计。                                                                                                    | 这篇论文说明 **Generator-Verifier co-evolution 本身已经是明确的研究路线**。EvoDrift-VL 的贡献因此要落在另一侧：共同进化时 Verifier 是否形成 generation-specific、lineage-specific 的错误盲区，以及怎样用 cross-lineage audit、counterfactual trace 和 temporal disagreement 识别与控制这种漂移。                              |     |
| 04  | [Self-Rewarding Language Models](https://proceedings.mlr.press/v235/yuan24d/yuan24d.pdf)                                                            | 传统对齐依赖固定的人类偏好数据和固定 reward model。随着模型能力提升，旧反馈会成为训练上限，同时继续收集高质量人工偏好成本很高。                          | 让 LLM 自己生成训练响应，再以 LLM-as-a-Judge 给自己的响应评分，根据自评结果构造 preference pair，并通过 DPO 迭代训练。                                                 | ① 当前模型 $M_t$ 为新指令生成多条 candidate response。<br>② 同一个 $M_t$ 切换成 Judge，对候选回答给出 0 到 5 分。<br>③ 每个 prompt 选最高分回答作为 chosen，最低分回答作为 rejected。<br>④ 将这些自生成 preference pairs 加入训练数据，通过 DPO 得到 $M_{t+1}$。<br>⑤ 新模型再次承担 Generator 与 Judge，重复多轮。这样 generation ability 与 reward ability 一起变化。                                                                          | 可把一轮抽象为 $r_i=J_{M_t}(x,y_i)$，$y^w=\arg\max_i r_i$，$y^l=\arg\min_i r_i$，随后 $M_{t+1}=\operatorname{DPO}(M_t,(x,y^w,y^l))$。这里最重要的关系是 **给训练信号的 Judge 也来自当前模型 $M_t$**。                                                                                                                            | 它提供了 IVD 的基础逻辑：self-reward 训练中评价者本身随模型更新。EvoDrift-VL 把这个问题推进到视觉 Agent、step-level trajectory verification 与同一 lineage 的跨代比较，并把关注点从“自评能否提升模型”转向“自评标准是否沿自身错误分布发生漂移”。                                                                                             |     |
| 05  | [Self-Preference Bias in LLM-as-a-Judge](https://arxiv.org/pdf/2410.21819.pdf)                                                                      | 当 LLM 同时参与生成和评价时，Judge 会偏向与自身生成分布更接近的回答。显式模型身份隐藏后，这种偏差仍可存在，因此来源不只在模型名称，还涉及输出分布和熟悉度。             | 用严格配对的 Judge 实验测量 self-preference，并分析回答 likelihood / perplexity 与偏好之间的关系，验证“熟悉的生成分布更容易获得偏好”的机制。                                  | ① 准备不同模型生成的成对回答，并用外部质量标签控制回答本身的优劣。<br>② 让多个 LLM Judge 做 pairwise evaluation，同时记录回答是否来自 Judge 自己。<br>③ 在真实质量相同或真实优胜方固定的条件下比较 self-generated 与 other-generated response 的获选率。<br>④ 进一步测量 Judge 对候选答案的 perplexity / likelihood，分析生成分布熟悉度与评价偏好的关系。                                                                                                          | 论文使用条件概率定义 self-preference bias：$\text{Bias}=P(Y'=1\mid S=1,Y=1)-P(Y'=1\mid S=0,Y=1)$。$Y$ 控制真实偏好结果，$S$ 表示候选是否来自 Judge 自身，$Y'$ 表示 Judge 的选择；两项之差隔离了输出来源带来的额外偏好。                                                                                                                               | 这篇论文直接对应 EvoDrift-VL 的 **style/familiarity confound**。如果 $V_i$ 更喜欢 $S_i$ 的轨迹，仅凭自然 rollout 仍可解释为语言风格、长度或工具调用模式更熟悉。Controlled Counterfactual Trace 要保持这些表面因素近似不变，只修改视觉事实、工具证据或逻辑步骤，才能把“熟悉度偏好”与“错误盲区”分开。                                                         |     |
| 06  | [DeepSeekMath: Pushing the Limits of Mathematical Reasoning in Open Language Models](https://arxiv.org/pdf/2402.03300.pdf)                          | PPO 用于 LLM 强化学习时需要额外训练 value / critic model，显存和计算开销较大。数学推理又天然适合对同一问题采样多条回答并进行结果比较。              | 提出 GRPO，用同一问题的一组 rollout reward 直接构造组内 baseline 和 relative advantage，省去单独的 critic model，再采用 PPO 风格的 clipped objective 更新 policy。 | ① 对问题 $q$ 从旧策略采样一组输出 $\{o_1,\ldots,o_G\}$。<br>② Reward Model 或可验证规则给每条输出得到 $r_i$。<br>③ 在组内对 reward 做均值与标准差归一化，得到每条输出的 relative advantage。<br>④ 对输出中各 token 使用同一个 outcome advantage，或使用 process reward 构造 step-level advantage。<br>⑤ 使用 clipped policy ratio 与 KL regularization 更新策略。                                                                   | Outcome supervision 下，$\hat A_{i,t}=\tilde r_i=\frac{r_i-\operatorname{mean}(\mathbf r)}{\operatorname{std}(\mathbf r)}$。它表示第 $i$ 条 rollout 相对于同组其他 rollout 的表现。GRPO 的关键是用组内 reward 统计量替代 PPO 的 learned value baseline。                                                                      | 它解释 EvoDrift-VL 中最关键的一条因果链：$V_t$ 产生的 reward 会通过 GRPO 改变 $M_{t+1}$。如果同代 Verifier 对某类错误出现系统性 false acceptance，这些错误轨迹就获得偏高 advantage，并被写回下一代共享 policy；由于 Solver 与 Verifier 共用模型，这种偏差具有继续累积的条件。                                                                   |     |

## 阅读重点

理解 EvoDrift-VL 时，最先确认三件事即可：Agent0-VL 中 Solver 与 Verifier 如何共用模型并通过 GRPO 更新；Preference Leakage 已经覆盖到什么程度的“同源评价偏好”；CoVerRL 已经如何定义和实现 Generator-Verifier co-evolution。其余三篇用于补齐 self-reward、self-preference confound 与 GRPO。
